# DS-SGen — Data Directory

Tracked copy of the cached pipeline artifacts and experimental results for the
DS-SGen (Distribution-Shift Selective Generation) project (10-701 IML, Spring 2026).

| Summary | |
|---|---|
| Total files | 37 (29 cache + 8 results) |
| Total apparent size | ~76 MB (75.9 MB cache + 663 KB results) |
| Largest file | `cache/nq_generations.json` (18 MB) |
| Schema version | 1 (stable across all committed runs) |
| Generator models | GPT-4o-mini (answers), DeBERTa-v2-xxlarge-mnli (entailment), all-MiniLM-L6-v2 (embeddings) |

---

## 1. Purpose

This directory is the **complete reproducibility bundle** for every empirical
result in the project. Given only this folder and the code in the repo, a
third party can re-run any downstream analysis (screening, method
comparison, epsilon sweeps) without access to:

- the OpenAI API (greedy and sampled answers are cached),
- a GPU (DeBERTa entailment scores and MiniLM embeddings are cached),
- any HuggingFace datasets (TriviaQA / NQ-Open / PopQA records are cached),
- any cluster filesystem.

Only the final `M1/M2/M3 × {synthetic, TQA→NQ}` downstream evaluation requires
Python + numpy + scikit-learn + matplotlib, and the complete sweep runs in
~90 seconds on a laptop with the caches already present.

```
    ├── baseline_results.json            # Method 1 (SGen-Semi) on TQA → NQ
    ├── conservative_results.json        # Method 2 (Conservative) on TQA → NQ
    ├── importance_weighted_results.json # Method 3 (DS-SGen) on TQA → NQ
    ├── epsilon_sweep_results.json       # Original 4-method × 4-ε sweep on TQA → NQ
    ├── screening_popqa_results.json     # Screening on PopQA head → tail
    ├── synthetic_final_screening.json   # Screening on synthetic pair (7/7 pass)
    ├── synthetic_final_eps_sweep.json   # Final 5-ε sweep (M1/M3 × {synth, TQA→NQ})
    └── synthetic_final_weight_quartile.json   # Covariate-vs-concept diagnostic
```

At runtime the code reads/writes via **symlinks** at the repo root:
`cache/` → `/data/user_data/anshulk/dsgen/cache` and `results/` → `/data/user_data/anshulk/dsgen/results`. Those symlinks are `.gitignore`d so they don't pollute the tree.

`data/cache/` and `data/results/` are **real file copies** — this is what's
actually committed to the repo.

## 4. JSON schemas

All JSONs are human-readable (indent=2) and follow these schemas:

### 4.1 `*_data.json` — normalized question records

```json
[
  {
    "idx": 0,
    "question": "What is the capital of France?",
    "reference_answer": "Paris",
    "all_answers": ["Paris"],
    "dataset": "synth_qa",
    "topic": "geography",       // synth_qa only
    "tier": 1                   // synth_qa only
  },
  ...
]
```

### 4.2 `*_generations.json` — GPT-4o-mini answers

```json
[
  {
    "idx": 0,
    "question": "What is the capital of France?",
    "greedy_answer": "The capital of France is Paris.",
    "mean_logprob": -0.0003,                  // f_M1 in the paper
    "token_logprobs": [-0.001, -0.0002, ...], // per-token greedy logprobs
    "sampled_answers": ["...", "...", "...", "...", "..."],
    "sampled_mean_logprobs": [-0.001, -0.002, -0.001, -0.0005, -0.002],
    "sampled_token_logprobs": [[...], [...], [...], [...], [...]],
    "_greedy_usage":  {"prompt": 25, "completion": 8},
    "_sampled_usage": {"prompt": 25, "completion": 42}
  },
  ...
]
```

### 4.3 `*_entailment.json` — DeBERTa entailment scores

```json
[
  {
    "idx": 0,
    "entail_score": 0.994,                    // P(ENTAILMENT) for greedy→reference
    "entail_label": 1,                        // 1 if argmax==ENTAILMENT else 0
    "fM2": 0.95,                              // self-consistency: bidirectional-entailment fraction
    "pairwise_entailments": [[true,true,...],...] // K×K directed entailment matrix
  },
  ...
]
```

`entail_label` is the binary correctness signal used everywhere downstream.

### 4.4 `*_embeddings.npy` — MiniLM sentence embeddings

Shape `(N, 384)`, dtype `float32`. `all-MiniLM-L6-v2` from
sentence-transformers. `np.load(path)` to read.

### 4.5 `synthetic_a_pair_indices.json` — pair definition

The `SyntheticPair` dataclass from `ds_sgen/synthetic_shift.py`:

```json
{
  "alpha": 0.75,
  "seed": 42,
  "K": 10,
  "fm1_cutoff": -0.4333,        // fM1 floor for the filter (0.0 quantile in final run)
  "n_pool": 1831,
  "source_idx": [234, 1402, 88, ...],   // 800 indices into synth_qa_data.json
  "target_idx": [56, 1798, 911, ...],   // 800 indices, disjoint from source_idx
  "A_topics": [0, 1, 3, 6, 8],  // cluster IDs in source-heavy partition
  "B_topics": [2, 4, 5, 7, 9],  // cluster IDs in target-heavy partition
  "source_topic_hist": [105, 109, 46, 66, 50, 57, 155, 50, 124, 38],
  "target_topic_hist": [39, 37, 127, 24, 116, 133, 52, 119, 38, 115],
  "source_acc": 0.815,
  "target_acc": 0.765
}
```

### 4.6 Method summary results

Methods 1 and 3 share a schema:

```json
{
  "config": { ...cfg section... },
  "cal_dataset": "tqa",

  "indomain": {

    "mean_efficiency": 0.822, "std_efficiency": 0.029

  "shifted":  { "label": "NQ", ... same structure ... },
```

## 6. Provenance

### 6.1 Base datasets

| Dataset | Hugging Face ID | Split | Sample size | Records on disk |
|---|---|---|---:|---:|
| NQ-Open | `google-research-datasets/nq_open` | validation | all | 3610 |
| TriviaQA | `mandarjoshi/trivia_qa` | validation, config `unfiltered.nocontext` | 3610 / 11313 (seed 42) | 3610 |
| PopQA | `akariasai/PopQA` | test | filtered by popularity score | 1000 head + 1000 tail |

All three are released under permissive research licenses (TriviaQA: Apache 2.0; NQ-Open: CC-BY-SA 3.0; PopQA: MIT). Record-level transformations are limited to schema normalization; no filtering that affects the distribution was applied except the PopQA popularity-threshold split.

### 6.2 Synthetic pool (`synth_qa_*`)

The 1831-item synthetic pool was generated on **2026-04-21** by:

1. **Question generation:** GPT-4o-mini (OpenAI chat completions API) in JSON mode, 30 batched calls (10 topics × 3 difficulty tiers), ~$0.05 OpenAI cost. See `ds_sgen/generate_synthetic_qa.py`.
2. **Validation filter:** length constraints (10–300 char questions, 1–6 word answers), question-mark required, no context-dependency markers. 2400 raw → 1831 after filter + dedupe (76.3% yield).
3. **Stage 1 answers:** GPT-4o-mini at temperature 0 (greedy) + temperature 0.7 (5 samples) per question. ~$0.22 OpenAI cost, ~48 minutes wall.
4. **Stage 2 entailment:** DeBERTa-v2-xxlarge-mnli on A6000 GPU. ~18 minutes wall.
5. **Stage 3 embeddings:** sentence-transformers `all-MiniLM-L6-v2`. ~1 minute wall.

SLURM job ID: **7346859** (the first run, which generated all four synth_qa caches before crashing on the downstream pair-size check — see the analysis doc §5).

### 6.3 Source/target pair (`synth_a_source_*`, `synth_a_target_*`, `synthetic_a_pair_indices.json`)

Derived from the synthetic pool by:

1. **KMeans clustering** on the 1831×384 MiniLM embeddings with K=10, random_state=42.
2. **Accuracy-sorted partition:** compute mean `entail_label` per cluster, assign top-5 clusters to A (source-heavy), bottom-5 to B (target-heavy).
3. **Weighted sampling without replacement:** source gets α=0.75 weight on A-items, target gets α=0.75 weight on B-items (disjoint from source).

Deterministic given the pool + seed=42. See `ds_sgen/synthetic_shift.py:build_synthetic_pair`.

SLURM job ID: **7352717** (the final ε sweep run, which reconstructed the pair at the start and wrote these caches).

### 6.4 Results files

- `baseline_results.json`, `conservative_results.json`, `importance_weighted_results.json`, `epsilon_sweep_results.json`, `screening_popqa_results.json` — pre-existing from the prior stage of the project; see `docs/method1_baseline_analysis.md`, `docs/method2_conservative_analysis.md`, `docs/method3_importance_weighted_analysis.md`, `docs/screening_analysis_popqa.md`.

## 8. Reproducibility notes

### 8.1 What's deterministic

Given the committed caches + `seed=42`, every downstream result is bit-exactly reproducible:

- KMeans clustering (K=10, random_state=42)
- Accuracy-sorted partition (deterministic given cluster labels + accuracies)
- Source/target sampling (`np.random.RandomState(42)`)
- M1/M3 split seeds (base_seed + s for s in range(500))
- Logistic regression in M3 (`LogisticRegression(random_state=seed)`)
- Deterministic plot output (matplotlib with fixed figsize and seed where applicable)

### 8.2 What's not deterministic

- **Synthetic pool generation itself** depends on GPT-4o-mini's temperature-1.0 sampling. Re-running `run_synthetic_a.py` from scratch (no cache) produces a *different* 1831-item pool, and downstream numbers differ slightly. The pool committed here is the exact pool from SLURM job 7346859.
- **DeBERTa entailment** uses float16 on GPU; sub-percent numerical differences across GPU models are possible. Differences below the significance of any downstream test.
- **OpenAI generations are frozen** in the committed cache. Re-generating would pull from an updated model, which could change the empirical accuracy by ~1 percentage point (within our error bars).

### 8.3 Verifying provenance

```bash
# Re-run the 4 success criteria on the committed data
python - <<'PY'
import json
sc = json.load(open("data/results/synthetic_final_screening.json"))
sw = json.load(open("data/results/synthetic_final_eps_sweep.json"))
wq = json.load(open("data/results/synthetic_final_weight_quartile.json"))

assert sum(sc[f"pass_{k}"] for k in ["1","2a","2b","3","4","5","6"]) == 7
assert sc["quartile_spread"] >= 0.05 and 0.03 <= sc["gap"] <= 0.15
assert wq["synthetic"]["Q1_minus_Q4"] >= 0.05 and wq["tqa_nq"]["Q1_minus_Q4"] < 0
crossover = [e for e in sw["synthetic"] if e["m1"]["validity_rate"] < 0.98 and e["m3"]["validity_rate"] >= 0.90]
assert crossover and min(e["epsilon"] for e in crossover) == 0.15
tqa_at_star = next(e for e in sw["tqa_nq"] if e["epsilon"] == 0.15)
assert tqa_at_star["m3"]["vacuous_frac"] > 0.50

print("All 4 success criteria verified from data/")
PY
```

Expected output: `All 4 success criteria verified from data/`.
